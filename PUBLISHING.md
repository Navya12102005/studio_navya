# Publishing Navya’s portfolio

The website is prepared as a static publishing package. It has not been deployed to a public host in this session.

## Build and preview

From the repository root:

```sh
node scripts/build.cjs
node scripts/server.cjs
```

The output is `dist/`. It includes the homepage, seven pre-rendered project stories, active artwork, social image, favicon, 404 page, robots file and response headers. Old visual experiments, original case pages, source PNGs, documentation and test scripts are excluded. Each new build replaces only a directory previously marked as generated by this build script.

## Verify the actual output

```sh
node scripts/release.cjs
```

This creates its own local preview server and runs the browser suites against the publishing output. It checks the deployment headers, 404 response, project reading without JavaScript, metadata generation, responsive interactions, the upper-body/brain/heart sequence, motion controls and mocked email delivery. It never sends a real email.

Regenerate the checked-in social image only after changing the visual identity:

```sh
node scripts/social.cjs
```

## Choose a host

- **Netlify:** the included `netlify.toml` uses `node scripts/build.cjs` and publishes `dist`.
- **Vercel:** the included `vercel.json` uses the same build and output directory, with matching response headers.
- **Manual static hosting:** upload the contents of `dist`, not the repository root. Configure equivalent headers if your host does not read `_headers`.

For Git-based deployment, the updated source must first be available in the repository selected by the host. For a manual upload, the generated package can be uploaded directly.

The build reads a public origin from `SITE_URL`, Netlify’s `URL`, or Vercel’s production/deployment URL. Once available, it writes an absolute social-image address, canonical URL, Open Graph URL, sitemap and sitemap entry in robots.txt. No domain is invented before a public address exists. After adding a custom domain, set `SITE_URL=https://your-actual-domain` in host settings and rebuild.

## Contact delivery is deliberately on hold

`config.js` currently has an empty Web3Forms key. The email-draft and copy fallback work without it. After the website has a public URL, complete Web3Forms verification and follow `CONTACT_SETUP.md`. Automated provider-response checks have passed; real inbox delivery has not been tested.

## After publishing

Open the public site on a phone and desktop, open a shared project link, check its social preview, and try the email fallback. Finish Web3Forms setup only afterward and verify one real message reaches the intended inbox.
